# Android ADB USB 权限问题处理

## 现象

Linux 上拔掉手机再重新插入后，Flutter 或 ADB 可能只能看到设备序列号，但无法读取设备属性：

```text
Error 1 retrieving device properties for 1d2238e3:
adb: insufficient permissions for device: user wuzuxian is not in the plugdev group

No supported devices found with name or id matching '1d2238e3'.

1d2238e3 (mobile) • 1d2238e3 • unsupported • Android null (API null) (unsupported)
```

此时设备不是 Flutter 不支持，而是当前 Linux 用户没有权限访问重新创建的 USB 设备节点。

## 原因

手机拔插后，Linux 会重新创建 `/dev/bus/usb/...` 设备节点。若当前用户没有加入 `plugdev` 组，或系统缺少 Android 设备对应的 `udev` 规则，`adb` 无法读取设备属性，Flutter 就会显示 `Android null (API null)` 和 `unsupported`。

本次问题中，设备信息为：

```text
Bus 003 Device 012: ID 2717:ff08 Xiaomi Inc. Redmi Note 3 (ADB Interface)
```

其中 `2717` 是 Android USB 设备的厂商 ID，需要写入 udev 规则。

## 一键修复

在项目根目录执行：

```bash
bash scripts/fix_adb_usb_permissions.sh
```

脚本会自动完成：

- 确保系统存在 `plugdev` 组。
- 将当前用户加入 `plugdev` 组。
- 从 `lsusb` 自动识别 Android ADB 设备的厂商 ID。
- 写入 `/etc/udev/rules.d/51-android.rules`。
- 重新加载并触发 `udev` 规则。
- 重启 `adb server`。
- 输出 `adb devices -l` 和 `flutter devices` 验证结果。

如果自动识别失败，可以手动传入厂商 ID：

```bash
bash scripts/fix_adb_usb_permissions.sh 2717
```

常见厂商 ID 示例：

```text
2717  Xiaomi
18d1  Google
12d1  Huawei
22b8  Motorola
04e8  Samsung
2a70  OnePlus
0bb4  HTC
0fce  Sony
```

## 手动处理步骤

如果不使用脚本，可以按下面步骤手动执行。

1. 确认当前用户组：

```bash
groups
```

如果输出中没有 `plugdev`，加入该组：

```bash
sudo usermod -aG plugdev "$USER"
```

2. 查询手机厂商 ID：

```bash
lsusb
```

找到 Android 手机对应行，例如：

```text
ID 2717:ff08 Xiaomi Inc. Redmi Note 3 (ADB Interface)
```

3. 写入 udev 规则：

```bash
sudo sh -c 'printf "%s\n" "SUBSYSTEM==\"usb\", ATTR{idVendor}==\"2717\", MODE=\"0666\", GROUP=\"plugdev\", TAG+=\"uaccess\"" > /etc/udev/rules.d/51-android.rules'
```

4. 重新加载规则并重启 ADB：

```bash
sudo udevadm control --reload-rules
sudo udevadm trigger
adb kill-server
adb start-server
```

5. 拔插手机，并在手机上重新确认 USB 调试授权。

6. 验证：

```bash
adb devices -l
flutter devices
```

修复后应看到类似结果：

```text
1d2238e3 device product:xun model:23073RPBFC device:xun
23073RPBFC (mobile) • 1d2238e3 • android-arm64 • Android 15 (API 35)
```

## 注意事项

- 加入 `plugdev` 后，建议退出桌面重新登录一次，确保新用户组在所有终端和 IDE 中生效。
- 不要长期使用 `sudo adb`。这会启动 root 拥有的 adb server，后续可能造成普通用户 adb 连接异常。
- 如果项目终端中找不到 `adb`，脚本会尝试使用默认路径 `$HOME/Android/Sdk/platform-tools/adb`。
