# 代码入库检测探针

项目通过两层机制落地开发规约：

- `custom_lint`：在 IDE、`flutter analyze` 和命令行中暴露架构违规。
- Git hook：在提交前运行工程级检查、Flutter analyzer 和自定义 lint。

## 安装

首次拉取项目后执行：

```sh
sh scripts/install_git_hooks.sh
flutter pub get
```

安装后，本地 Git 会使用 `.githooks/pre-commit` 作为提交前检查入口。

## 手动检查

```sh
dart run scripts/check_project_rules.dart --staged
flutter analyze
dart run custom_lint
```

## 当前探针覆盖范围

- 禁止业务代码直接使用 `Navigator.push` 等命令式导航。
- 禁止 `context.go('/path')`、`context.push('/path')` 等硬编码路由路径。
- 禁止 ViewModel import `flutter/material.dart`、`dart:ui` 或依赖 `BuildContext`。
- 禁止 View 层直接 import Service / Repository / API / Database。
- 禁止常见用户可见文案硬编码在 `Text(...)`、`tooltip`、`hintText`、`errorText` 等位置。
- 检查 `pubspec.yaml` 中是否存在项目规约要求的基础依赖和本地 lint 依赖。

## 说明

Git hook 默认检查已暂存文件，并额外运行全量 `flutter analyze` 与 `dart run custom_lint`。如果历史代码还未完成规约迁移，提交会被阻断，应先修复对应违规或在 PR 中拆分迁移提交。
