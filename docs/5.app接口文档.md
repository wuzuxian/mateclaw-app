# 1.接口约定
1. app接口约定
- 登录接口使用移动端接口 `POST /api/mobile/user/login`
- 登录成功后返回 `Authorization: Bearer <token>` 所需的 JWT
- 退出登录接口使用移动端接口 `POST /api/mobile/user/logout`
- 后续业务接口默认需要携带 `Authorization`
- 所有接口响应统一遵守 `R<T>` 包裹格式
- 注册成功后，移动端用户只拥有且只返回一个工作空间；后续业务请求固定使用该工作空间

|参数名|参数类型|是否必填|备注|
|---|---|---|---|
|code|整数|是|状态码，成功时为 `200`|
|msg|字符串|是|提示信息|
|data|对象/数组/空|是|业务数据，失败时可为空|

# 2.用户相关
## 2.1 手机用户登录接口
```http request
POST /api/mobile/user/login
Content-Type: application/json
```

请求参数：

|参数名|参数类型|是否必填|参数位置|备注|
|---|---|---|---|---|
|username|字符串|是|body|用户名|
|password|字符串|是|body|密码|

请求参数示例：
```json
{
  "username": "admin",
  "password": "123456"
}
```

响应值：

`data` 字段说明：

|参数名|参数类型|是否必填|备注|
|---|---|---|---|
|id|整数|是|用户 ID|
|token|字符串|是|JWT token|
|username|字符串|是|用户名|
|nickname|字符串|是|昵称|
|role|字符串|是|角色，`admin` / `user`|

响应值示例：
```json
{
  "code": 200,
  "msg": "操作成功",
  "data": {
    "id": 1,
    "token": "eyJhbGciOiJIUzI1NiJ9...",
    "username": "admin",
    "nickname": "管理员",
    "role": "admin"
  }
}
```

接口逻辑：
```text
1. 根据 username 查询启用状态的用户
2. 使用 BCrypt 校验 password
3. 校验失败时返回 401，提示“用户名或密码错误”
4. 校验成功后生成 JWT token，并返回用户基础信息
5. 登录接口有 IP 级限流，1 分钟内最多 5 次，超限返回 429
```

## 2.2 手机用户注册接口
```http request
POST /api/mobile/user/register
Content-Type: application/json
```

请求参数：

|参数名|参数类型|是否必填|参数位置|备注|
|---|---|---|---|---|
|username|字符串|是|body|用户名，需唯一|
|password|字符串|是|body|密码|
|nickname|字符串|否|body|昵称，不传时默认使用用户名|
|workspaceName|字符串|否|body|个人工作空间名称，不传时默认使用昵称或用户名|

请求参数示例：
```json
{
  "username": "demo",
  "password": "123456",
  "nickname": "小明",
  "workspaceName": "小明的工作台"
}
```

响应值：

`data` 字段说明：

|参数名|参数类型|是否必填|备注|
|---|---|---|---|
|token|字符串|是|JWT token|
|user|对象|是|注册后的用户信息|
|workspace|对象|是|注册后自动创建的唯一工作空间|

`user` 字段说明：

|参数名|参数类型|是否必填|备注|
|---|---|---|---|
|id|整数|是|用户 ID|
|username|字符串|是|用户名|
|nickname|字符串|是|昵称|
|role|字符串|是|角色，固定为 `user`|

`workspace` 字段说明：

|参数名|参数类型|是否必填|备注|
|---|---|---|---|
|id|整数|是|工作空间 ID|
|name|字符串|是|工作空间名称|
|slug|字符串|是|工作空间标识|
|role|字符串|是|当前用户在该工作空间的角色，固定为 `owner`|

响应值示例：
```json
{
  "code": 200,
  "msg": "操作成功",
  "data": {
    "token": "eyJhbGciOiJIUzI1NiJ9...",
    "user": {
      "id": 1001,
      "username": "demo",
      "nickname": "小明",
      "role": "user"
    },
    "workspace": {
      "id": 2001,
      "name": "小明的工作台",
      "slug": "demo-1001",
      "role": "owner"
    }
  }
}
```

接口逻辑：
```text
1. 校验 username 是否已存在
2. 使用 BCrypt 加密 password 并创建用户，默认 role = user、enabled = true
3. 基于新用户创建一个独立工作空间，workspaceName 不传时默认使用 nickname 或 username
4. 复用现有工作空间创建逻辑：自动写入 owner 关系，并种子化默认 tasks 会话
5. 该用户在移动端仅保留一个工作空间，后续业务请求统一使用该 workspace
6. 返回 JWT token、用户信息和唯一工作空间信息
```

## 2.3 手机用户退出登录接口
```http request
POST /api/mobile/user/logout
Authorization: Bearer <token>
```

请求参数：

无。

响应值：

`data` 固定为 `null`。

响应值示例：
```json
{
  "code": 200,
  "msg": "操作成功",
  "data": null
}
```

接口逻辑：
```text
1. 校验 Authorization 中的 JWT token
2. 服务端不维护移动端 token 会话状态时，退出登录由客户端清除本地 token 完成
3. 客户端收到成功响应后清除 Authorization、用户信息和当前工作空间缓存，并返回登录页
```
